{{- if .Values.restore.enabled }}

5. An import is armed. The application pod runs it before the webserver starts, once, and then
   records a marker on the data volume so later restarts skip it. Watch it rather than the
   rollout — a large archive takes a while and the pod stays in Init the whole time:

     kubectl logs -n {{ include "common.namespace" . }} -l app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/component=server -c import -f

   Two things the export does not carry, and that you have to do by hand afterwards: API tokens
   are not exported and every client needs a new one, and the search index is rebuilt with
   `kubectl exec ... -- document_index reindex` if search comes back empty.

   NOTE: a `.zip` export is extracted in full into the scratch directory before it is read.
   persistence.scratchSizeLimit is {{ .Values.persistence.scratchSizeLimit | default "unbounded" }} —
   it has to exceed the archive's uncompressed size, or the pod is evicted part-way through the
   import and the next start begins again.

   An attempt that dies part-way — evicted, OOM-killed, its node drained — is retried from the
   start on the next boot: the files it had already copied are cleared first, because the importer
   will not overwrite them. That is bounded to what the failed attempt itself wrote, so it costs
   time rather than data. If it happens repeatedly, raise restore.resourcesPreset or lower
   restore.batchSize rather than letting it cycle.

   Once it has completed you can leave `restore.enabled` set; it is a no-op from then on.

   WARNING: the archive is downloaded from a URL while a NetworkPolicy is in force and

WARNING: backups are scheduled but metrics.prometheusRule.enabled is false, so nothing alerts when
they stop. A CronJob that quietly stops firing — suspended, or missing its starting deadline every
run — produces no failed Job and no error anywhere; the only evidence is a `last successful time`
that stops advancing. Enable the rules, or put your own alert on
`kube_cronjob_status_last_successful_time`.
{{- end }}
{{- if not .Values.backup.upload.enabled }}

NOTE: the export stays on a PersistentVolume in this cluster. That survives a mistake in the web
UI; it does not survive losing the cluster or the storage backing it. Set `backup.upload` to ship
it somewhere else, or point a cluster backup tool at the export claim.
{{- end }}
{{- if not (include "paperless-ngx.hasCredential" (dict "ctx" . "value" .Values.backup.passphrase)) }}

itself. Set `backup.passphrase` — and store it somewhere other than the backup.
